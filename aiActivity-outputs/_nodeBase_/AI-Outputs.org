* What This File Is

A *central, cross-project ledger* of action items, defects and findings that
Claude turns up while working --- items whose scope is *global*, not specific
to whichever project they happened to be discovered in.

It lives in =mother/= and is symlinked next to =CLAUDE.md= in each
aiActivity base, the same way =AI-WORKFLOW.org= is. One file, many projects,
edits visible everywhere immediately.

** Keywords

Entries use the not-done states declared in =#+TODO:= above:

| Keyword    | Meaning                                                  |
|------------+----------------------------------------------------------|
| =TODO=       | Needs fixing. No workaround known, or none needed.       |
| =WORKAROUND= | Broken, *and* a workaround is documented and in use. Still |
|            | needs an upstream fix. Highest broadcast value --- these |
|            | save the next Claude from rediscovering the breakage.    |
| =INFO=       | Captured knowledge. No action required.                  |
| =DONE=       | Resolved. Archivable via =/bx-archive=.                    |

Each actionable entry carries a =:REPO:= property naming where the fix
belongs --- these items are found in one repo and fixed in another, so
without it dispatch becomes guesswork once the context is gone.

* Defects --- BISOS Framework Packages

** WORKAROUND =sysdSysUnit remove= is broken
:PROPERTIES:
:REPO: /bisos/git/bxRepos/bisos-pip/debian
:FOUND: 2026-09-10
:END:

- *Where*: =bisos/debian/bifSystemd_csu.py:307=
- *What*: =if self._serviceFilePath.is_file():= --- =_serviceFilePath= is a
  =str=, not a =pathlib.Path=. Raises
  =AttributeError: 'str' object has no attribute 'is_file'=.
- *Impact*: =remove= (documented "stop + disable + unlink") is advertised in
  the examples output of *every* planted systemd unit, so it looks
  supported. It fails before doing anything --- safely, but with a raw
  traceback.
- *Observed*: =airflow-webserver-sysd.pcs -i sysdSysUnit remove=. Unit
  remained active, enabled, and on disk.

*Workaround*: decompose into the three sub-actions it was meant to chain.
All three work:

#+begin_example
<unit>-sysd.pcs -i sysdSysUnit stop
<unit>-sysd.pcs -i sysdSysUnit disable
<unit>-sysd.pcs -i configFileDelete --cls="configFile_sysdUnit" --runAs="root"
#+end_example

** WORKAROUND =cbs_reMaterialize= is broken
:PROPERTIES:
:REPO: /bisos/git/bxRepos/bisos-pip/capability
:FOUND: 2026-09-11
:END:

- *Where*: =bisos/capability/cba_csu.py=, in =cbs_reMaterialize.cmnd()=
- *What*: calls =cbs_materialize().pyCmnd(argsList=[""])=, but
  =cbs_materialize= declares =cmndArgsLen = {'Min': 0, 'Max': 0}= and its
  =cmnd()= accepts no =argsList=. Raises
  =TypeError: cbs_materialize.cmnd() got an unexpected keyword argument 'argsList'=.
- *Impact*: fails at dispatch, so *nothing* runs --- not even the
  =cbmSymlinkToThisCbs enable= step that precedes it. Fails safely.
- *Observed*: =airflow-cbs.pcs -i cbs_reMaterialize= --- exit 1, no leaf
  created, no units written.

*Workaround*: run the two halves separately.

#+begin_example
<name>-cbs.pcs -i cbmSymlinkToThisCbs enable
<name>-cbs.pcs -i cbs_materialize
#+end_example

*Also check*: =cbs_deMaterialize= ("Disable + UnMaterialize") is the mirror
command and was never exercised --- likely the same shape of bug.

** TODO Unit templates fail *silently* when the binary is not on PATH
:PROPERTIES:
:REPO: /bisos/git/bxRepos/bisos-pip/debian
:FOUND: 2026-09-11
:END:

- *Where*: the generic =sysdUnitFileFunc()= pattern in seeded units, e.g.
  =bisos-pip/airflow/py3/bin/airflow-*-sysd.pcs=:

  #+begin_src python
  if ( execPath := pathPlus.whichBinPath("airflow",) ) is None: return None
  #+end_src

- *What*: when the binary is absent the function returns =None=, and
  =configFileStdout= / =configFileUpdate= emit *empty output with no
  diagnostic*. No unit file is written and nothing says why.
- *Impact*: the behaviour is correct (better than writing a broken unit) but
  invisible. A materialization that silently produces zero unit files is
  indistinguishable from one that never ran.
- *Observed*: after removing airflow from =/bisos/venv/py3/bisos3=, all four
  units rendered empty. Only recognisable because it had been predicted.
- *Wanted*: report loudly, e.g.
  ="airflow not found on PATH -- cannot generate unit; run the sbom first"=.
- *Scope*: generic seeded pattern --- affects any =bisos.debian=-seeded unit
  in any package, not just airflow.

** TODO =AptPkg(func=...)= has no idempotency gate
:PROPERTIES:
:REPO: /bisos/git/bxRepos/bisos-pip/sbom
:FOUND: 2026-09-11
:END:

- *Where*: =bisos/sbom/sbom_csu.py:397-404= (apt), =:580-586= (pip),
  =:936-944= (npm)
- *What*: the only gate before calling =func()= is
  =aptPkg_isInstalled(name)=. For a *func-bearing pseudo-package* --- a name
  that is not a real apt package --- that predicate can never be true, so
  =func()= runs on *every* =sbom_fullUpdate=.
- *Impact*: a sharp edge rather than a crash. Anyone using =func== for
  one-time setup (=useradd=, =mkdir=, writing =/etc= files) gets it
  re-executed on every materialize; non-idempotent functions fail on the
  second run (=useradd= exits 9).
- *Handled locally*: =airflowAcctEnvSetup()= in =airflow-sbom.pcs= was made
  idempotent --- =id airflow >/dev/null 2>&1 || sudo useradd ...=,
  =mkdir -p=, and writing =/etc/default/airflow= only when absent so
  hand-added overrides survive re-runs.
- *Wanted*: either a separate idempotency predicate on =AptPkg=, or explicit
  documentation of the re-run contract. Currently discoverable only by
  reading =sbom_csu.py=.

* Captured Knowledge

** INFO Airflow 3 splits across distributions --- =pip uninstall apache-airflow= is not enough

=pip uninstall apache-airflow= leaves a *fully working* Airflow.
=apache-airflow= is an umbrella shim; the =airflow/= package and the
=airflow= console script come from *=apache-airflow-core=*, with
=apache-airflow-task-sdk= and the =apache-airflow-providers-*= packages
alongside.

Observed: uninstalling the umbrella reported success, and =airflow version=
still printed =3.3.1=.

Removing Airflow from a venv means removing all of: =apache-airflow=,
=apache-airflow-core=, =apache-airflow-task-sdk=, and every
=apache-airflow-providers-*=.

Why it mattered: =whichBinPath()= resolves by PATH order. A surviving
=bisos3= copy at PATH position 11 would have beaten the intended =asc= venv
at position 18, and the systemd units would have been baked with the old
venv path while appearing correctly migrated.
